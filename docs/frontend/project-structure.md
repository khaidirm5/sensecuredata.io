# Frontend Project Structure

## Overview

The frontend is built with React and Vite.

The source code is organized into separate directories for pages, reusable components, routing, application state, hooks, API services, layouts, types, utilities, and styling.

The current frontend structure is:

```text
frontend/
├── eslint.config.js
├── index.html
├── package.json
├── package-lock.json
├── vite.config.js
├── public/
│   ├── favicon.svg
│   └── icons.svg
└── src/
    ├── App.css
    ├── App.jsx
    ├── assets/
    ├── components/
    ├── contexts/
    ├── hooks/
    ├── index.css
    ├── layouts/
    ├── main.jsx
    ├── pages/
    ├── routes/
    ├── services/
    ├── styles/
    ├── types/
    └── utils/
```

`node_modules/` is generated by npm and is not part of the application source structure.

## Root Files

### `index.html`

The main HTML entry point used by Vite.

### `package.json`

Contains the frontend project metadata, npm scripts, dependencies, and development dependencies.

### `package-lock.json`

Locks the installed npm dependency versions for reproducible installations.

### `vite.config.js`

Contains the Vite configuration used by the frontend application.

### `eslint.config.js`

Contains the ESLint configuration used to check frontend source code.

## Public Assets

The `public/` directory contains static assets that can be served directly by the frontend.

```text
public/
├── favicon.svg
└── icons.svg
```

These files are separate from assets imported directly through the React source code.

## Source Directory

The main application source code is located under `src/`.

### `main.jsx`

The frontend application entry point.

It initializes the React application and mounts it to the HTML document.

### `App.jsx`

Contains the main application component and acts as a central part of the frontend application composition.

### `App.css`

Contains styling associated with the main application component.

### `index.css`

Contains global frontend styles.

## Components

```text
src/components/
```

Contains reusable React components used across different parts of the application.

Components are intended to keep UI elements separated from page-level composition.

## Contexts

```text
src/contexts/
```

Contains React context implementations used to share application-level state or functionality between components.

## Hooks

```text
src/hooks/
```

Contains reusable React hooks.

Hooks allow shared frontend logic to be separated from individual page or component implementations.

## Layouts

```text
src/layouts/
```

Contains layout components used to provide shared page structures.

Layouts can be used to keep common UI structures separate from individual pages.

## Pages

```text
src/pages/
```

Contains page-level React components.

Pages represent the main screens or views exposed by the frontend application.

## Routes

```text
src/routes/
```

Contains frontend routing configuration.

Routing is separated from individual page implementations so that navigation and page composition can be managed independently.

## Services

```text
src/services/
```

Contains frontend service modules used for communication with backend APIs and other application-level service operations.

The frontend communicates with the FastAPI backend through the API layer rather than accessing the PostgreSQL database directly.

## Styles

```text
src/styles/
```

Contains additional styling resources used by the frontend.

Global styles that apply to the application are kept separately from component-specific styling where appropriate.

## Types

```text
src/types/
```

Contains frontend type definitions used to keep data structures consistent across the application.

## Utils

```text
src/utils/
```

Contains reusable utility functions that do not belong to a specific page or component.

## Assets

```text
src/assets/
```

Contains assets that are imported and used by the React application.

These assets are handled through the Vite build process.

## Frontend Organization

The current organization separates the frontend into several responsibilities:

React Application
│
├── Entry Point
│   └── main.jsx
│
├── Application
│   └── App.jsx
│
├── Pages
│   └── pages/
│
├── Routing
│   └── routes/
│
├── Layouts
│   └── layouts/
│
├── Reusable UI
│   └── components/
│
├── Shared State
│   └── contexts/
│
├── Reusable Logic
│   └── hooks/
│
├── API / Services
│   └── services/
│

│   └── types/

## Frontend and Backend Communication

The frontend communicates with the FastAPI backend through HTTP requests.

The overall application flow is:

```text
User
  ↓
React Frontend
  ↓
Pages / Components
  ↓
Services
  ↓
FastAPI REST API
  ↓
Backend Application Layers
  ↓
PostgreSQL
```

The frontend does not connect directly to PostgreSQL.

## Current Architecture

The frontend is part of the project's current modular monolith architecture.

```text
Web Browser
    ↓
React + Vite
    ↓
FastAPI
    ↓
Application Layers
    ↓
PostgreSQL
```

The backend remains a single FastAPI application. A future move toward microservices is part of the project roadmap and is not the current frontend deployment architecture.
